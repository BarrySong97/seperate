# 中英双语(App + 官网) — 实现计划

- 日期:2026-09-29
- 已定的决策(用户选择):
  - **App**:默认跟随 macOS 系统语言(系统首选语言是中文 → 中文,其余一律英文);菜单里加「语言 / Language」:跟随系统 / 中文 / English,**切换后重启 Seperate 生效**。
  - **官网**:英文放 `/`,中文移到 `/zh`(`/zh/changelog`)。导航栏加语言切换,`hreflang` 互指。
  - **更新日志**:现有 0.1.0、0.2.0 由 agent 翻成英文;以后每次发版中英文一起写。
- 只支持两种语言:`en`、`zh-Hans`。

## 方案概述

### App:内联双语 `tr("中文", "English")`

每条界面文案在调用处写成一对:`tr("关闭 Tab", "Close Tab")`。`tr` 在启动时按当前语言选一边返回。

为什么不用 Apple 的 `.xcstrings` / `Localizable.strings`:
- 我们的 `.app` 由 `scripts/build-app.sh` 手工组装,没有 Xcode 工程;String Catalog 要额外编译步骤和资源 bundle 拷贝,构建链变复杂。
- 只有两种语言、约 335 条文案。内联写法**不会漏译**(少一个参数就编译不过),改文案时两种语言就在同一行,review 一眼看清。
- 代价:以后要加第三种语言得改成表驱动。已明确只支持两种,可以接受。

语言怎么定:
- 菜单选择写入 app 自己的 `UserDefaults` 的 `AppleLanguages`(选「跟随系统」就删掉这个键)。这是 macOS 标准做法,**Sparkle 的更新窗口、系统提供的菜单项和按钮也会一起跟着变**。
- `tr` 读 `Bundle.main.preferredLocalizations.first`:以 `zh` 开头 → 中文,否则英文。
- `Info.plist` 加 `CFBundleDevelopmentRegion = en`、`CFBundleLocalizations = [en, zh-Hans]`,bundle 里放 `en.lproj` / `zh-Hans.lproj`(系统靠它们判断 app 支持哪些语言)。
- 为什么要重启:AppKit 视图和菜单大多只建一次,即时刷新要改遍每个视图,风险大。重启时弹一次确认。

### 官网:按语言分两棵路由

- `src/i18n/`:`en.ts`、`zh.ts` 两份文案字典,类型相同(少一条 TypeScript 就报错)。
- 路由:`/`、`/changelog` 渲染英文;`/zh`、`/zh/changelog` 渲染中文,两边共用同一套组件,只是传入的 `lang` 不同。每种语言有自己的根 layout,`<html lang>` 分别是 `en` / `zh-CN`(先按 `node_modules/next/dist/docs/` 确认 Next 16 静态导出下多根 layout 的写法)。
- 页面元信息(title、description、Open Graph、sitemap、robots)两种语言都生成,互相用 `alternates.languages` 指向对方。
- 首页 mock、特性卡片、更新日志 mock 里的界面文字也按语言切换,让英文页面里画的是英文界面。
- 访问 `/` 的中文浏览器:**不自动跳转**(静态站点没法在服务端判断,自动跳转还会让首屏闪一下),只在顶部显示一条「切换到中文」的小提示,关掉后记住。

### 更新日志

- 目录改成 `content/changelog/en/<ver>.md` 和 `content/changelog/zh/<ver>.md`,两边 frontmatter 相同(版本、日期、媒体、补丁),正文和标题各自写。
- 构建时检查:某个版本只有一种语言就构建失败,防止漏写。
- `website/README.md` 的写法规则改成双语;agent 记忆里的「更新日志规则」同步更新。

## 风险 / 注意
- **用户数据不动**:数据库里已有的 Workspace 名、会话标题都是用户数据,不翻译;只有新建时的默认值按语言。持久化的枚举 raw value 不改。
- `AppleLanguages` 只写 app 自己的域,不碰全局偏好。
- 英文通常比中文长:侧栏、Tab、顶栏摘要、按钮宽度要在英文下逐个看有没有截断。
- 拼音搜索只对中文标题有意义,英文界面下保留(用户数据里仍可能有中文标题)。
- 官网 `/changelog` 等旧中文链接会变成英文页面(你选的方案);页面上有语言切换,影响不大。
- 这是一次较大的界面改动,适合作为 0.3.0 发布;发版仍要你明确说。
